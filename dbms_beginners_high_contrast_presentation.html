Slide 2 • Core Definitions & History

Database vs. DBMS: The Interface & The Vault

A DBMS acts as a protective bridge (interface) between the raw Database and your user applications.

Electronic Storage

1. Database (DB)

An organised collection of data stored electronically on a computer system, made up of tables where each table holds info on a specific topic.

📱 Smartphone Example
Your phone's internal storage chip holding separate tables for Contacts, Call Logs, and Gallery Photos.
Passive Container: Simply holds the structured data.
Management Software

2. DBMS Software

Software that helps us store, retrieve, and manipulate data in a database. It protects data by restricting unauthorized access across multiple users.

📱 Smartphone Example
The SQLite Engine inside Android/iOS that fetches "Mom" when you type her name and blocks random apps from reading your messages!
Active Guard & Manager: Interface between apps & data.
Did You Know? The very first DBMS was developed in the early 1960s by Charles Bachman.
Smart Home Gadgets: Devices like Alexa or smart lights also rely on databases to work!

The 6 Components of a DBMS

A DBMS bridges the Machine Side (Hardware & Software) with the Human Side (Procedures & People) using Data & Access Language!

1

Hardware

Machine

Physical parts: Keyboard, mouse, touchscreen, CPU processor, and storage disks (Hard Disk / Flash memory).

📱 Phone: Processor, Screen & 128GB Flash Chip
2

Software

Machine

Programs that understand database languages. Examples: MySQL, Oracle, SQL Server, MS Access, FileMaker, dBase, Clipper (and discontinued FoxPro).

📱 Phone: Android / iOS & SQLite Engine
3

Data & Metadata

Core Bridge

Data: Raw facts (your selfie).
Metadata (Data about data): File size (3MB), name, date, and GPS location!

📱 Phone: Photo Pixels + "Taken Today at 5 PM"
4

Access Language

Core Bridge

Language used to give commands to get, modify, or delete data. Most widely used: SQL (Structured Query Language).

📱 Phone: SQL commands running behind your taps
5

Procedures

Human

General instructions & rules: How to set up, install, log in/out, manage, create backups, and generate reports.

📱 Phone: Nightly Cloud Backup & PIN Unlock Rules
6

People ("Live-ware")

Human

The most crucial part! Comprises Database Administrators (DBAs), Software Developers, and End-Users.

📱 Phone: You (End-User) & App Developers
Slide 6 • The 4 Main Types of DBMS (Pages 83–85)

The 4 Types of DBMS

Each database model organizes data differently depending on the app's needs:

1960s • Tree Model

1. Hierarchical

Like an upside-down tree: 1 Parent has 0 or more Children. Top is Root, endpoints holding actual data are Leaves. Easy to add/remove, hard to search deep items. Used in Windows Registry & XML.

🌳 Root (Phone Storage)
├── 📁 Child 1 (Photos)
└── 🍃 Grandchild 1 (Trip.jpg)
└── 📁 Child 2 (Music)
📱 Mobile: File Manager Folder Tree
Most Common!

2. Relational (RDBMS)

Stores data in tables (called relations) with rows & columns, linked together via relationships. Uses SQL. Examples: MySQL, MS SQL Server, Oracle.

student_idnamegrade
S101Aman7
S102Ramya7
S103Raj7
📱 Mobile: Contacts + Call Logs (Next Slide!)
Not Only SQL

3. NoSQL DBMS

Flexible storage (Key-Value, Document, Column-family, Graph) where each key can have different columns! Great for Big Data. Examples: MongoDB, Cassandra, DynamoDB, Redis.

Riya: {email, gender, age}
Arya: {email, gender}
Rakesh: {email, country, hair}
📱 Mobile: Instagram Feeds & WhatsApp Media
Objects & Classes

4. Object-Oriented

Stores data as Objects (boxes holding attributes & relationships). Many similar objects form a Class. Used in telecom, engineering & social media.

Sahil : Employee
• works ➔ Technical Dept
• lives ➔ Delhi
• has ➔ 9967188451

Why Split Into 2 Linked Tables? (Primary & Foreign Keys)

Look at what happens in your phone's Call History when Rahul calls you 3 times!

❌ The Bad Way

1 Giant Single Table

If we store everything in one single table, Rahul's phone number, city, and photo get copied every single time he calls!

Time Name Phone City
10:00 AM Rahul 98110... Delhi
11:15 AM Rahul 98110... Delhi
04:30 PM Rahul 98110... Delhi
Massive Redundancy: Repeats identical data 1,000 times, wasting phone storage!
Update Problem: If Rahul moves to Mumbai, you must edit hundreds of rows!
✅ The Smart RDBMS Way

Split Into 2 Tables & Link With Keys!

Slide 8 • Objects of a Database (Page 81)

The 4 Objects of a Database

The building blocks used to store, enter, search, and present data efficiently:

1. Tables

The basic building blocks. A collection of rows (each row = a single record) and columns (each column = a piece of data/attribute).

📱 Mobile Analogy: The Contacts table holding 500 rows (friends) and columns (Name, Number, Email).
Storage Foundation

2. Forms

User-friendly interfaces used to enter, edit, or get data. Used to create new records, update existing ones, or delete records easily.

📱 Mobile Analogy: The "Create New Contact" screen with clean text boxes and a Save button.
Friendly Input Screen

3. Queries

A request for data. Used to retrieve, store, update, or delete data, generate reports, perform data analysis, and find & fix data errors.

📱 Mobile Analogy: Searching "Mom" or filtering "Photos taken in Hyderabad".
Smart Data Request

4. Reports

Displays database data in a formatted and organised way. Used to generate invoices, statements, mailing lists, and printable summaries.

📱 Mobile Analogy: Your weekly Digital Wellbeing Screen-Time chart or PDF phone bill.
Formatted Summary
